# План: ScriptVault как самостоятельное приложение

Цель: убрать всё, что осталось от шаблона Google AI Studio, вычистить лишнее, повысить безопасность и качество кода, улучшить продукт. План разбит на фазы: от «обязательно» к «желательно».

---

## 1. Что сейчас есть (результаты анализа)

**Стек:** React 19 + TypeScript + Vite + Tailwind 4, Firebase Auth (Google OAuth), Google Apps Script API, Google Drive API v3, GitHub REST/Git Data API, JSZip, PrismJS.

**Размер:** ~9 000 строк, из них UI-компоненты ~5 500 (два компонента — `CodeWorkspace.tsx` 1447 строк и `GitHubPanel.tsx` 1513 строки — это половина приложения).

**Рабочие сценарии (их не трогаем, только усиливаем):**
подключение проекта по Script ID / URL / Sheets → редактирование кода → запуск функций → локальные коммиты с diff → откат → бэкап-снимки на Google Drive → пуш в GitHub → автосинхронизация по таймеру.

### 1.2. Проблемы качества и безопасности

1. **GitHub PAT в `localStorage`** — причём сохраняется _список токенов_ (`scriptvault_saved_github_tokens`). Это главная дыра: любой XSS/расширение/человек за компом вытащит токен. README сам об этом предупреждает — значит, проблема известная и её надо решать, а не документировать.
2. **История версий в `localStorage`** (полные снимки файлов в каждом коммите). Квота ~5 МБ — историю начнёт молча теряться (ошибки только в `console.error`). Нужен IndexedDB.
3. **`tsconfig` без `strict`**, нет ESLint/Prettier, скрипт `lint` — это просто `tsc --noEmit`. Тестов нет вообще, CI нет.
4. **Локальный runner через `new Function`** — исполняет код скрипта в контексте страницы с упрощёнными моками. Ограничен, небезопасен и создаёт ложное чувство «запуска».
5. **Гигантские компоненты** (1400–1500 строк) + весь стейт в `App.tsx` + прокидывание пропов — любое изменение дорого и опасно.
6. **Нет Error Boundary** — упавший компонент роняет всё приложение в белый экран.
7. **После обновления страницы** Google access token живёт только в памяти (`firebaseAuth.ts`) — пользователь вынужден логиниться заново. UX-проблема.
8. **i18n «на глаз»** — русские/английские строки размазаны по компонентам тернарниками.
9. **README с битой разметкой** (экранированные ` ``` `, `\`` внутри маркдауна).
10. **Нет LICENSE-файла**, хотя README заявляет Apache 2.0.
11. **Rate limit / retry** — при 429 от Google/GitHub запросы просто падают; нет backoff.
12. Слово «real-time» в описании — это polling; в интерфейсе и README надо называть вещи своими именами (README уже объясняет, но метаданные/описание — нет).

## 2. Что убираем (cleanup — сделать первым, это быстро и безопасно)

- [ ] Удалить `metadata.json`, `firebase-applet-config.json`.
- [ ] Выкинуть неиспользуемые зависимости: `@google/genai`, `express`, `@types/express`, `dotenv`, `esbuild`, `tsx`, `motion`, `autoprefixer` (Tailwind 4 через vite-плагин его не требует).
- [ ] Переписать `.env.example` под реальные переменные:
  - `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_OAUTH_CLIENT_ID`.

- [ ] Переименовать пакет `react-example` → `scriptvault`, добавить `engines`, `description`, `license`.
- [ ] Почистить `vite.config.ts` (убрать `DISABLE_HMR`-логику), `package.json` (`clean`).
- [ ] Сделать демо-скрипты опциональными: пустое состояние + кнопка «Загрузить пример», а не автозаполнение.
- [ ] Поправить README: нормальные код-блоки, честные формулировки про polling, актуальная структура проекта.
- [ ] Добавить `LICENSE` (Apache 2.0) и `.nvmrc`/`engines` (Node 18+).

**Результат:** репозиторий выглядит и ведёт себя как нормальное standalone-приложение, `bun install` ставит только нужное.

## 3. Фазы развития

### Фаза A — Фундамент качества ✅ (выполнено)

- [x] `strict: true` в `tsconfig` — код проходит без ошибок.
- [x] ESLint 9 (flat config: typescript-eslint, react-hooks, unused-imports) + Prettier; `lint` — это ESLint, `typecheck` — tsc.
- [x] GitHub Actions: на каждый push/PR — `typecheck + lint + test + build`.
- [x] Error Boundary на корне приложения (восстановление вместо белого экрана).
- [x] Vitest + happy-dom: 31 тест на `gitService` (diff, коммиты, откат) и `appsScriptService` (парсеры ID и функций).
- [x] TypeScript закреплён на 6.0.3: typescript-eslint пока не поддерживает нативный TS 7 (tracked: typescript-eslint#10940).

### Фаза B — Безопасность (2–3 дня)

- [ ] **GitHub-токены:** убрать в `sessionStorage` (умирает при закрытии вкладки) с явным чекбоксом «запомнить» (тогда — зашифрованный через WebCrypto ключом из пароля пользователя), показывать только маску `ghp_****`. Убрать хранение _списка_ токенов, один активный.
- [ ] Либо (лучше для продакшена) — **тонкий backend-прокси** (Cloudflare Workers / Cloudflare Pages Functions / тот же Firebase Cloud Functions), который держит GitHub-токен в секрете и проксирует GitHub API. Клиент вообще не видит PAT. Это же откроет дорогу к вебхукам GitHub.
- [ ] CSP-заголовки, `Referrer-Policy`, запрет inline-eval в проде.
- [ ] Пересмотр OAuth-скоупов: `drive` — самый широкий; сузить до `drive.file` где возможно, задокументировать почему каждый скоуп нужен.
- [ ] Ограничить/изолировать локальный runner (см. Фазу D) — до тех пор хотя бы предупреждать «код выполняется в вашем браузере».

### Фаза C — Архитектура и хранилище (3–5 дней)

- [ ] **Слой хранилища:** `storage.ts` с интерфейсом `get/set/list`, реализация на IndexedDB (`idb`) для истории коммитов и снимков; миграция данных из localStorage при первом запуске. Квота вырастает с ~5 МБ до сотен МБ.
- [ ] **Состояние:** вынести из `App.tsx` в Zustand (или Context + custom hooks): `useAuth`, `useProjects`, `useHistory`, `useSync`, `useGitHub`, `useLogs`. Убрать проп-дрейлинг.
- [ ] **Разбор гигантских компонентов:**
  - `CodeWorkspace` → `FileTree`, `EditorPane`, `RunPanel`, `ProjectToolbar`, `DiffViewer`;
  - `GitHubPanel` → `RepoConnectForm`, `BranchManager`, `CommitHistory`, `PushDialog`, `RepoCreateDialog`;
  - `BackupDrivePanel` → `FolderPicker`, `SnapshotList`, `SyncSettings`.
- [ ] **HTTP-клиент:** общий `apiFetch` с retry + exponential backoff на 429/5xx, единый формат ошибок (`Result<T>` или error-классы), нормальные сообщения для пользователя (сейчас разнобой).

## 5. Принятые решения (октябрь 2026)

1. **Архитектура:** чистое статическое SPA (Firebase Hosting / любой статик-хост), **без backend**. Хостить-обслуживать нечего, аудитория — «для себя + возможно ещё кто-то». Слой сервисов проектируем так, чтобы позже при необходимости подключить тонкий backend-прокси для GitHub-токена (без переписывания UI).
2. **Локальный runner:** оставляем как «песочницу для быстрого теста», но переносим исполнение из `new Function` в странице в **изолированный Web Worker** (без DOM), с честной пометкой «эмуляция, ограниченно». Реальный запуск — через Apps Script API.
3. **Аудитория:** личное использование, возможны сторонние пользователи → делаем базовую безопасность (токены, CSP), без мультитенантности и тяжёлого auth.
4. **Объём:** сначала P0 (чистка) + Фаза A/B (фундамент: strict TS, ESLint, CI, тесты, безопасность, IndexedDB), затем продуктовые фичи из Фазы D по порядку «Must → Should → Could». Язык интерфейса — ru/en, по умолчанию ru.
